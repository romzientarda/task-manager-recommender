# Подбор приложения для управления задачами

Веб-сервис помогает выбрать подходящее приложение для личного управления задачами. Пользователь последовательно указывает требования к приложению, сравнивает понравившиеся интерфейсы и получает итоговый топ-3 с процентом совпадения, преимуществами и возможными ограничениями каждого варианта.

**Рабочая версия сайта:** [открыть веб-приложение](https://romzientarda.github.io/task-manager-recommender/)

## Назначение проекта

На рынке существует большое количество приложений для ведения задач, однако их набор функций, доступность, внешний вид и удобство заметно различаются. Самостоятельное сравнение занимает время и часто сводится к просмотру рекламных описаний.

Сайт упрощает выбор: он сопоставляет требования конкретного пользователя с характеристиками приложений и формирует персональные рекомендации. При этом учитываются не только функциональные возможности, но и визуальное предпочтение пользователя — на отдельном этапе он выбирает наиболее понравившийся интерфейс.

1. наличие мобильной версии для смартфона;
2. возможность использовать решение для личного управления задачами, а не только для полноценного проектного планирования с общей изменяемой рабочей средой.

После предварительного отбора приложения сравниваются по единому набору критериев.

## На чем основан подбор

В основе сайта находится сравнительная матрица характеристик. Для каждого приложения по каждому критерию хранится одно из двух значений:

- `1` — возможность присутствует;
- `0` — возможность отсутствует или выражена недостаточно.

Такая модель соответствует обозначениям «+» и «−» в исходной таблице сравнительного анализа. Промежуточное значение `+/−` не используется.

Пользователь не выставляет приложению оценку напрямую. Вместо этого он указывает, насколько важен для него каждый критерий. Ответ преобразуется в числовой вес:

| Ответ пользователя | Вес |
|---|---:|
| Не нужно / не важно | 0 |
| Скорее нужно / скорее важно | 1 |
| Нужно / важно | 2 |
| Очень нужно / очень важно | 3 |

Чем выше вес, тем сильнее соответствующий критерий влияет на итоговый процент совпадения.

## Как работает сайт

Подбор состоит из трех последовательных этапов.

### 1. Выбор отношения к стране приложения

Пользователь выбирает один из пяти вариантов:

- только российское приложение;
- российское приложение желательно;
- страна не важна;
- зарубежное приложение желательно;
- только зарубежное приложение.

При строгом выборе «только российское» или «только зарубежное» приложения другой группы исключаются из основного ранжирования.

При мягком предпочтении приложения выбранной группы получают дополнительный вес, но решения другой группы также могут попасть в рекомендации, если лучше соответствуют функциональным требованиям.

Если страна не важна, российские и зарубежные приложения сравниваются на равных.

### 2. Последовательный опрос по критериям

Пользователь отвечает на 13 вопросов. Каждый вопрос связан с одним критерием и определяет его вес от 0 до 3.

Используются следующие критерии:

1. возможность постановки отдельных задач;
2. уведомления или напоминания о дедлайнах;
3. скорость добавления новой задачи;
4. возможность бесплатного использования;
5. работа без VPN;
6. наличие календаря;
7. инструменты отслеживания прогресса;
8. простота изменения планов;
9. автоматическая постановка повторяющихся задач;
10. разделение задач по папкам, спискам или тегам;
11. отсутствие рекламы;
12. настройка внешнего вида и формата задач;
13. наличие версии для ПК.

Ответы можно изменять, возвращаясь к предыдущим вопросам и этапам. После изменения ответа рейтинг пересчитывается заново.

### 3. Выбор интерфейса

После расчета предварительного рейтинга пользователю попарно показываются реальные скриншоты интерфейсов приложений.

При наличии не менее шести вариантов сравниваются пары:

- 5-е и 6-е место — выбранное приложение занимает третье место итогового топа;
- 3-е и 4-е место — выбранное приложение занимает второе место;
- 1-е и 2-е место — выбранное приложение занимает первое место.

Если доступных вариантов меньше, лишние пары автоматически пропускаются:

- при 4–5 вариантах показываются пары 3–4 и 1–2;
- при 2–3 вариантах показывается только пара 1–2;
- при одном основном варианте этап попарного выбора не требуется.

Интерфейс не дает приложению дополнительные баллы. Выбор пользователя напрямую определяет, какое приложение из каждой пары попадет на соответствующее место итогового топ-3.

## Подробный принцип расчета рекомендаций

Для каждого приложения рассчитывается взвешенное совпадение с ответами пользователя.

Пусть:

- `wᵢ` — важность i-го критерия, выбранная пользователем, от 0 до 3;
- `fᵢ` — характеристика приложения по i-му критерию: 1, если возможность есть, и 0, если ее нет;
- `n` — количество критериев, равное 13.

Сумма набранных баллов приложения рассчитывается так:

```text
Набранные баллы = Σ(wᵢ × fᵢ)
```

Максимально возможная сумма для ответов конкретного пользователя:

```text
Максимум = Σwᵢ
```

Процент совпадения:

```text
Совпадение = Набранные баллы / Максимум × 100%
```

Критерии с весом `0` не влияют ни на набранные баллы, ни на максимально возможную сумму. Поэтому приложение не получает преимущества и не теряет процент за функцию, которая пользователю не нужна.

### Учет мягкого предпочтения страны

Если пользователь выбирает вариант «российское желательно» или «зарубежное желательно», к расчету добавляется отдельный вес, равный 3 баллам:

```text
Максимум = Σwᵢ + 3
```

Приложение предпочитаемой группы получает эти 3 балла:

```text
Набранные баллы = Σ(wᵢ × fᵢ) + 3
```

Для приложения другой группы дополнительные 3 балла не начисляются. Это создает умеренное преимущество, но не заменяет основное сравнение по функциям.

### Формирование предварительного рейтинга

Приложения сортируются по следующим правилам:

1. по сумме набранных баллов — от большей к меньшей;
2. при равенстве — по проценту совпадения;
3. при полном равенстве — по названию в алфавитном порядке.

Предварительный рейтинг используется для формирования пар интерфейсов.

### Формирование итогового топ-3

Выбранные пользователем интерфейсы занимают заранее определенные позиции:

- победитель пары 1–2 становится рекомендацией № 1;
- победитель пары 3–4 становится рекомендацией № 2;
- победитель пары 5–6 становится рекомендацией № 3.

Если некоторые пары отсутствовали и итоговых вариантов меньше трех, свободные позиции автоматически заполняются приложениями, которые находятся ближе всего к требованиям пользователя по предварительному рейтингу. Повторяющиеся приложения не допускаются.

Поэтому сайт всегда стремится сформировать три рекомендации, даже когда после строгого отбора или при небольшом количестве кандидатов этап выбора интерфейса содержит меньше трех пар.

## Что получает пользователь

Для каждого приложения в итоговом топ-3 отображаются:

- место в рейтинге;
- название приложения;
- страна происхождения;
- реальный скриншот интерфейса;
- процент совпадения с ответами;
- краткое описание;
- функции, которые хорошо соответствуют требованиям;
- возможности, наличие которых лучше дополнительно проверить.

Процент показывает функциональную близость приложения к ответам пользователя. Он не является общей оценкой качества приложения и не зависит от популярности бренда.

## Используемые технологии

Сайт реализован как адаптивное одностраничное веб-приложение:

- **HTML5** — структура страниц и элементов интерфейса;
- **CSS3** — оформление, адаптивная верстка и отображение на компьютерах и смартфонах;
- **JavaScript** — хранение данных, обработка ответов, расчет процентов, формирование пар и итогового топ-3;
- **GitHub Pages** — публикация сайта в интернете по постоянной ссылке.

Дополнительные библиотеки и серверная часть не используются. Все вычисления выполняются непосредственно в браузере пользователя. Ответы не отправляются на внешний сервер и не сохраняются после закрытия страницы.

└── screenshots/

- `assets/screenshots` содержит изображения интерфейсов.

## Публикация и обновление

Сайт публикуется через GitHub Pages из основной ветки репозитория. После изменения файлов и сохранения нового коммита опубликованная версия автоматически обновляется по той же ссылке. Отдельная версия сайта для смартфона не требуется: адаптивное отображение работает в рамках одного `index.html`.
